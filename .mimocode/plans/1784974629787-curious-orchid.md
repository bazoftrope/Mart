# План: Администрирование — расширение до управления пользователями

## Текущее состояние

Базовый механизм бутстрапа админа **уже работает**:
- `ADMIN_EMAIL` + `ADMIN_PASSWORD_HASH` в `.env.local`
- При логине с этими credentials → `ensureAdminUser()` создаёт/обновляет запись в БД
- Регистрация блокирует admin email и роль admin

**Проблема:** нет UI для управления пользователями после первого входа.

## Рекомендация: 2 шага

### Шаг 1: Настройка .env.local

Добавить в `.env.local`:
```
ADMIN_EMAIL=admin@yourdomain.com
ADMIN_PASSWORD_HASH=<сгенерировать bcrypt hash>
```

Генерация хеша: `node -e "console.log(require('bcrypt').hashSync('ваш_пароль', 10))"`

Убедиться что `.env.example` содержит эти переменные с комментариями.

### Шаг 2: Страница управления пользователями в админ-панели

**Что добавляем:**
- `/admin/users` — список всех пользователей с фильтрацией по роли
- Возможность изменить роль пользователя (mentor ↔ participant)
- Просмотр профиля пользователя (email, имя, роль, дата регистрации)

**Что НЕ добавляем (MVP):**
- Создание пользователей через UI (через регистрацию)
- Деактивация/удаление (нет в схеме БД)
- Multi-admin через UI (через env vars)
- Onboarding wizard

```typescript
// Body: { role: 'mentor' | 'participant' }
```

## Навигация (Layout.tsx)

```
admin → "Марафоны на проверке" (/admin)
      → "Пользователи" (/admin/users)  ← новое
      → "Выйти"
```

## Верификация

1. Добавить `ADMIN_EMAIL` и `ADMIN_PASSWORD_HASH` в `.env.local`
2. Запустить `npm run dev`
3. Залогиниться как админ → видим навигацию с "Пользователи"
4. Перейти на `/admin/users` → видим список зарегистрированных пользователей
5. Кликнуть на пользователя → видим профиль и можем изменить роль
6. Попытаться изменить свою роль → ошибка (защита)
7. Залогиниться как обычный пользователь → не видим ссылку "Пользователи"
8. Попробовать зайти на `/admin/users` без роли admin → редирект на `/login`
